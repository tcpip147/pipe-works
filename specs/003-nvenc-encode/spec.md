# 기능 명세: NVENC 영상 인코딩

**기능 식별자**: `003-nvenc-encode`  
**작성일**: 2026-09-14  
**상태**: 초안

## 개요

GPU 프레임을 NVENC으로 압축해 송출 단계가 사용할 `EncodedPacket`으로 변환한다. 입력 프레임의 코덱·해상도·시간 기준과 인코더가 부여한 타임스탬프를 보존한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 - GPU 프레임 인코딩 (우선순위: P1)

운영자는 디코딩·추론된 프레임을 지정 GPU에서 연속적으로 인코딩해 송출 단계로 전달받는다.

**검증**: 모의 인코더가 반환한 패킷이 입력 순서대로 출력되고 메타데이터가 보존되는지 확인한다.

### 사용자 스토리 2 - 인코더 종료 패킷 배출 (우선순위: P2)

운영자는 입력 프레임 스트림이 끝날 때 인코더 내부에 남은 패킷도 손실 없이 받을 수 있어야 한다.

**검증**: 입력 종료 후 `EndEncode` 결과가 모두 출력되는지 확인한다.

### 사용자 스토리 3 - 송신 재접속 후 키프레임부터 출력 재개 (우선순위: P1)

운영자는 RTSP 송신 연결이 새로 생성되거나 송신 오류에서 복구된 후, 디코더가 즉시 복원 가능한 키프레임부터 출력이 재개되기를 원한다.

**검증**: 재접속 대기 상태에서 키프레임 이전 패킷은 송출하지 않고, 첫 키프레임부터 순서대로 송출되는지 확인한다.

## 기능 요구사항

- **FR-001**: 시스템은 첫 GPU 프레임의 해상도, 픽셀 형식, GPU 번호, 코덱을 사용해 인코더를 한 번 초기화해야 한다.
- **FR-002**: 시스템은 모든 입력 프레임을 인코더에 순서대로 전달하고 반환된 패킷을 순서대로 출력해야 한다.
- **FR-003**: 출력 패킷은 입력 프레임에서 보존한 코덱, 너비, 높이, 시간 기준과 인코더가 생성한 타임스탬프 및 패킷 데이터를 포함해야 한다.
- **FR-004**: 입력 스트림이 종료되면 인코더 종료 처리를 수행하고 잔여 패킷을 출력해야 한다.
- **FR-005**: B-frame 재정렬을 사용하지 않아 입력과 출력의 지연을 최소화해야 한다.
- **FR-006**: 시스템은 새 RTSP 송신 연결을 만들거나 송신 오류에서 복구한 뒤, H.264/H.265 IDR 키프레임을 만날 때까지 후속 패킷을 송출하지 않아야 하며, 첫 IDR 키프레임부터 출력 재개해야 한다.

## 성공 기준

- **SC-001**: 모의 인코더 검증에서 입력 프레임 100개 이상이 누락 없이 처리된다.
- **SC-002**: 코덱·너비·높이·시간 기준은 입력 프레임과 출력 패킷에서 100% 일치하고, PTS는 인코더가 반환한 timestamp와 일치한다.
- **SC-003**: 종료 시 잔여 패킷이 100% 출력된다.
- **SC-004**: 송신 연결 생성 또는 송신 오류 후 복구 검증에서 첫 IDR 키프레임 전의 패킷은 0개 송출되고, 첫 IDR 키프레임은 100% 송출된다.

## 가정 및 범위

- 인코더 라이브러리와 GPU 프레임의 수명은 호출자가 보장한다.
- RTSP 컨테이너화와 송출 연결 복구는 `send.py`의 책임이다.

## 추가 운영 계약

- 입력 프레임이 없으면 `EndEncode()`를 호출하지 않는다.
- `Encode()`가 여러 패킷을 반환하면 반환 순서를 유지한다.
- 인코더 timestamp는 출력 PTS로 사용하며 입력 PTS와 동일하다고 가정하지 않는다.
- `Encode()` 또는 `EndEncode()` 예외는 별도 복구하지 않고 상위 호출자에게 전파한다.

## 현재 구현 기준

- 구현 파일은 `src/nvidia_pipe/encode.py`이다. 파이프라인이 전달한 CUDA stream을
  `cudastream`으로 인코더에 전달하고, 같은 PyTorch stream 컨텍스트에서 `Encode()`를
  호출한다.
- 현재 출력은 H.264/H.265 입력 코덱을 유지하고 B-frame을 사용하지 않는다(`bf=0`).
  첫 입력 프레임의 평균 FPS를 가장 가까운 정수로 변환해 `fps`, `gop`, `idrperiod`에
  동일하게 적용한다. 따라서 IDR 키프레임 목표 주기는 약 1초이다. 평균 FPS가 없거나
  0 이하이면 경고를 기록하고 30fps를 사용한다.
- 각 인코더 패킷의 native `timestamp`를 `EncodedPacket.pts`로 보존한다. 입력 프레임의
  PTS와 동일하다고 가정하지 않는다.
