# 연구: GPU 추론 결과 CPU 큐

## 결정: 결과는 `GpuFrame`에 붙여 CLI에서 제출한다

**근거**: 추론 콜백은 모델 결과만 만들고, 파이프라인 실행 계층은 stream·worker·수명주기를 관리한다. 모델 재로드가 발생해도 공통 결과 큐가 중복 생성되지 않는다.

**검토한 대안**: 예제 모델 안에서 worker를 직접 생성한다. 모델 모듈 재로드 시 worker 중복과 종료 누락 위험이 있어 채택하지 않는다.

## 결정: 결과만 pinned CPU 버퍼로 비동기 복사한다

**근거**: 차량 상자 같은 결과는 작고, 영상 NV12 프레임을 CPU로 복사하지 않아 GPU 영상 경로를 보존한다.

**검토한 대안**: 결과를 GPU 텐서 상태로 프로세스 큐에 전달한다. CUDA IPC와 producer 수명 관리가 필요하므로 범위를 벗어난다.

## 결정: 완료 확인에는 `Event.query()`를 사용한다

**근거**: `query()`는 완료 여부만 즉시 반환하며 메인 프레임 처리 경로를 기다리게 하지 않는다.

**검토한 대안**: `Event.synchronize()`를 worker에서 호출한다. 구현은 단순하지만 명시적 동기화 요구사항에 맞지 않아 채택하지 않는다.

## 결정: 큐는 최신 우선으로 동작한다

**근거**: 실시간 영상에서는 오래된 결과보다 최신 결과가 더 중요하며, 느린 소비자가 GPU 파이프라인을 역압박하지 않아야 한다.
