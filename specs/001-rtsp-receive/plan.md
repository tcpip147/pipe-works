# 구현 계획: RTSP 영상 수신

**기능 식별자**: `001-rtsp-receive` | **작성일**: 2026-09-14 |
**명세**: [spec.md](spec.md)

**입력**: `src/nvidia_pipe/receive.py` RTSP 영상 수신 단계의 기능 명세

## 요약

지원되는 RTSP 영상 소스에서 압축 영상 패킷과 원본 시간 정보를 수신하여 NVDEC 단계에
안전하게 전달한다. 연결과 읽기 제한 시간을 적용하고, 연결 또는 읽기 오류가 발생하면
연결을 정리한 뒤 3초 간격으로 재시도한다. 수신 패킷은 bitstream 버퍼의 소유권을
명확히 유지하여 하드웨어 디코더가 유효한 데이터를 읽을 수 있게 한다.

## 기술적 맥락

**언어/버전**: Python 3.11.9

**주요 의존성**: PyAV 18.1.0, PyNvVideoCodec 2.2.2, PyYAML 6.0.3

**저장소**: 해당 없음

**검증**: Python 구문 검사, 단위 검증 추가, 접근 가능한 RTSP 소스를 이용한 통합 검증

**대상 플랫폼**: NVIDIA GPU와 CUDA 런타임이 구성된 Windows 환경

**프로젝트 유형**: 단일 프로세스 영상 파이프라인 라이브러리 및 CLI

**성능 목표**: 정상 소스에서 수신 시작 후 5초 안에 첫 유효 패킷을 전달하고, 연결 실패
후 3초 간격으로 재연결을 시도한다.

**제약 조건**: 지원 코덱은 H.264, H.265, HEVC이며, 원본 PTS/DTS와 시간 기준을
변형하지 않는다. 압축 bitstream의 수명은 NVDEC 디코드 호출이 끝날 때까지 유지해야 한다.

**범위**: 파이프라인 하나당 RTSP 입력 영상 스트림 하나의 수신, 검증, 재연결 및
`ReceivedPacket` 전달을 다룬다. 디코드·추론·인코드·송출 정책은 범위 밖이다.

## 헌법 준수 확인

### 설계 전 확인

| 원칙 | 상태 | 설계 반영 |
|---|---|---|
| 엔드투엔드 실시간 파이프라인 | 통과 | 수신 단계는 최신 소스 패킷을 순서와 시간 정보와 함께 전달한다. |
| GPU 경로와 자원 격리 | 통과 | 압축 입력만 CPU 경계에서 보유하고 NVDEC용 패킷을 GPU 디코드 단계에 전달한다. |
| 송출 복구와 정상성 기준 | 해당 없음 | 이 기능은 입력 수신만 담당한다. |
| 관측 가능하고 실패를 숨기지 않는 운영 | 통과 | 연결 시도, 스트림 특성, 오류, 재시도를 기록한다. 미지원 코덱은 명확한 실패로 표면화한다. |
| 단순한 감독 구조와 명확한 종료 | 통과 | 수신 연결은 반복마다 명시적으로 정리하며 별도 프로세스를 만들지 않는다. |
| 한글 문서화 | 통과 | 생성된 계획과 설계 문서는 한글로 작성한다. |

복잡성 예외는 없다.

### 설계 후 재확인

조사와 데이터 모델 설계 후에도 모든 원칙을 충족한다. bitstream 버퍼의 강한 참조를
수신 패킷에 포함하는 설계는 불필요한 복사가 아니라 NVDEC 입력 포인터의 유효 기간을
보장하기 위한 필수 안전 조치다.
