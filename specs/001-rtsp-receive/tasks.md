**검문점**: 수신과 디코드 사이의 데이터 계약이 버퍼 수명 요구를 표현한다.

## 3단계: 사용자 스토리 1 - 지원되는 영상 스트림 수신 (우선순위: P1) 🎯 MVP

**목표**: 지원되는 RTSP 영상 패킷과 시간·키프레임 정보를 안전하게 NVDEC 단계에 전달한다.

**독립 검증**: 모의 H.264 RTSP 스트림에서 유효 패킷을 수신하고, 코덱·시간·키프레임·버퍼
참조를 가진 수신 패킷이 생성되는지 확인한다.

- [X] T004 [US1] `tests/nvidia_pipe/test_receive.py`에 유효 H.264 패킷의 PTS, DTS, 길이,
  키프레임, bitstream 소유권 보존 테스트를 작성한다.
- [X] T005 [US1] `src/nvidia_pipe/receive.py`에서 압축 bitstream 버퍼를 `ReceivedPacket`과
  함께 보유하고 유효 패킷 메타데이터를 구성하도록 구현한다.

**검문점**: 유효한 지원 코덱 입력은 다음 디코드 단계가 소비 가능한 패킷으로 전달된다.

---

## 4단계: 사용자 스토리 2 - 수신 연결 자동 복구 (우선순위: P2)

**목표**: 일시적인 연결 또는 읽기 실패 뒤 자원을 정리하고 3초 후 자동 재연결한다.

**독립 검증**: 첫 연결이 실패하고 다음 연결이 성공하는 모의 소스에서 재시도 대기, 컨테이너
정리, 새 패킷 전달을 확인한다.

- [X] T006 [US2] `tests/nvidia_pipe/test_receive.py`에 연결 실패 뒤 3초 대기와 재연결을
  검증하는 테스트를 작성한다.
- [X] T007 [US2] `src/nvidia_pipe/receive.py`에서 연결·읽기 오류 처리, 컨테이너 정리,
  재시도 로그를 명확히 구현한다.

**검문점**: 복구 가능한 오류는 파이프라인을 영구 중단시키지 않고 수신을 재개한다.

---

## 5단계: 사용자 스토리 3 - 지원하지 않는 입력의 명확한 거부 (우선순위: P3)

**목표**: 지원하지 않는 코덱을 재연결 대상으로 오인하지 않고 명확한 오류로 종료한다.

**독립 검증**: 모의 미지원 코덱 입력에서 오류 로그가 남고 `ValueError`가 호출자에게
전달되며 패킷이 산출되지 않는지 확인한다.

- [X] T008 [US3] `tests/nvidia_pipe/test_receive.py`에 미지원 코덱 거부와 오류 로그 테스트를
  작성한다.
- [X] T009 [US3] `src/nvidia_pipe/receive.py`에서 미지원 코덱 오류를 기록하고 재연결 없이
  호출자에게 전달하도록 구현한다.

**검문점**: 설정 또는 호환성 오류가 운영 로그와 프로세스 종료 상태에 반영된다.

## 의존성과 실행 순서

- T001 → T002 → T003이 모든 사용자 스토리의 기반이다.
- US1은 T003 이후, US2는 US1의 수신 계약 이후, US3은 US1의 스트림 검증 이후 수행한다.
- 권장 순서는 T001~T005 → T006~T007 → T008~T009 → T010~T012이다.
- 다른 개발자가 있다면 T006과 T008의 테스트 초안은 T005 이후 병렬로 준비할 수 있다.

## 구현 전략

1. bitstream 버퍼 수명 문제를 먼저 해결하고 유효 입력 수신을 검증한다.
2. 연결 복구와 미지원 코덱 거부를 각각 독립 검증으로 추가한다.
3. 단위 검증을 통과한 뒤 실제 RTSP 및 GPU 환경에서 빠른 검증 안내를 수행한다.
