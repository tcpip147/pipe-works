# 데이터 모델: RTSP 영상 수신

## 수신 설정

| 필드 | 설명 | 검증 규칙 |
|---|---|---|
| RTSP 주소 | 입력 영상 소스의 주소 | 비어 있지 않아야 한다. |
| 전송 방식 | RTSP 전송 방식 | 지원되는 전송 방식이어야 한다. |

## 영상 스트림 정보

| 필드 | 설명 | 검증 규칙 |
|---|---|---|
| 코덱 이름 | 소스가 사용하는 영상 코덱 | H.264, H.265, HEVC 중 하나여야 한다. |
| 해상도 | 영상의 너비와 높이 | 양수여야 한다. |
| 프레임 속도 | 소스가 보고한 평균 프레임 속도 | 알 수 없을 수 있으므로 기록 목적에만 사용한다. |
| 시간 기준 | 패킷 시간값을 해석하는 기준 | 원본 값을 변경하지 않는다. |

## 수신 패킷

| 필드 | 설명 | 검증 규칙 |
|---|---|---|
| 코덱 식별자 | NVDEC가 사용할 코덱 식별자 | 지원된 코덱에 대응해야 한다. |
| 원본 스트림 | 해상도와 시간 기준의 출처 | 현재 연결의 영상 스트림이어야 한다. |
| bitstream 버퍼 | 압축 영상 바이트와 소유권 | 디코드 호출이 끝날 때까지 강한 참조를 유지한다. |
| 입력 패킷 데이터 | NVDEC 디코드 호출이 소비하는 메타데이터 | bitstream 버퍼의 주소와 크기를 정확히 가리켜야 한다. |
| PTS | 표시 순서를 나타내는 원본 시간값 | 비어 있으면 패킷을 전달하지 않는다. |
| DTS | 디코드 순서를 나타내는 원본 시간값 | 비어 있으면 패킷을 전달하지 않는다. |
| 길이 | 이전 유효 PTS와의 차이 | 첫 유효 패킷은 원본 길이를 사용하며, 음수 차이는 0으로 처리한다. |
| 키프레임 여부 | 독립 디코드 가능 여부 | 원본 패킷의 값을 보존한다. |

## 상태 전이

```text
연결 시도 → 스트림 검증 → 패킷 수신 → 패킷 전달
    ↑                         │
    └── 3초 대기 ← 오류 감지 ──┘
```

- 지원하지 않는 코덱은 스트림 검증에서 오류로 기록되며 패킷 전달 상태로 진행하지 않는다.
- PTS 또는 DTS가 없는 패킷은 현재 연결을 유지하되 해당 패킷만 건너뛴다.
- 연결 또는 읽기 오류는 열린 자원을 정리한 뒤 재시도 대기로 전이한다.
