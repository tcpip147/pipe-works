# 기능 명세: RTSP 영상 수신

**기능 식별자**: `001-rtsp-receive`

**작성일**: 2026-09-14

**상태**: 초안

**입력**: `src/nvidia_pipe/receive.py`의 RTSP 영상 수신 동작 명세화

## 사용자 시나리오 및 검증

### 사용자 스토리 1 - 지원되는 영상 스트림 수신 (우선순위: P1)

영상 파이프라인 운영자는 설정한 RTSP 영상 소스에서 지원되는 코덱의 영상 패킷을
연속으로 수신하여 이후 디코드 단계에 전달할 수 있어야 한다.

**우선순위 근거**: 안정적인 수신이 없으면 디코드, 추론, 인코드, 송출의 어느 단계도
동작할 수 없다.

**독립 검증**: 지원되는 코덱의 접근 가능한 RTSP 주소를 설정하고, 수신 단계가 순서와
시간 정보를 가진 영상 패킷을 하나 이상 전달하는지 확인한다.

**인수 시나리오**:

1. **조건** 지원되는 영상 코덱의 접근 가능한 RTSP 소스가 있을 때, **행동** 수신을
   시작하면, **결과** 영상 패킷과 영상 스트림 정보가 다음 단계에 전달된다.
2. **조건** 수신 중인 영상 스트림이 있을 때, **행동** 연속된 영상 패킷이 도착하면,
   **결과** 각 패킷의 표시 시간, 디코드 시간, 길이 및 키프레임 정보가 보존된다.

---

### 사용자 스토리 2 - 수신 연결 자동 복구 (우선순위: P2)

운영자는 일시적인 RTSP 연결 실패나 소스 단절 후에도 수동 개입 없이 수신이 다시
시도되기를 원한다.

**우선순위 근거**: 카메라 또는 네트워크의 일시 장애가 전체 파이프라인의 영구 중단으로
이어져서는 안 된다.

**독립 검증**: 정상 수신 중인 RTSP 소스를 일시적으로 끊었다가 복구하고, 수신이 정해진
재시도 간격 후 자동으로 다시 시작되는지 확인한다.

**인수 시나리오**:

1. **조건** RTSP 소스 연결이 실패했을 때, **행동** 수신 단계가 실패를 감지하면,
   **결과** 실패 원인을 기록하고 3초 후 다시 연결을 시도한다.
2. **조건** 연결 실패 뒤 RTSP 소스가 복구되었을 때, **행동** 다음 연결 시도가
   성공하면, **결과** 수신 단계는 새 영상 패킷 전달을 재개한다.

---

### 사용자 스토리 3 - 지원하지 않는 입력의 명확한 거부 (우선순위: P3)

운영자는 하드웨어 디코더가 지원하지 않는 영상 코덱을 입력으로 설정했을 때 원인을
식별할 수 있어야 한다.

**우선순위 근거**: 지원하지 않는 입력을 정상처럼 처리하면 이후 단계의 실패 원인을
추적하기 어렵다.

**독립 검증**: 지원 대상이 아닌 영상 코덱의 RTSP 소스를 설정하고, 수신이 해당 입력을
전달하지 않으며 코덱 미지원 사실을 명확히 보고하는지 확인한다.

**인수 시나리오**:

1. **조건** 지원하지 않는 영상 코덱의 RTSP 소스가 있을 때, **행동** 수신을 시작하면,
   **결과** 지원하지 않는 코덱이라는 오류가 기록되고 유효하지 않은 패킷은 전달되지
   않는다.

### 예외 상황

- 영상 스트림이 없는 RTSP 소스는 영상 패킷을 전달하지 않고 연결 실패로 처리한다.
- 표시 시간 또는 디코드 시간이 없는 패킷은 시간 순서 보장이 불가능하므로 전달하지
  않고 경고를 기록한다.
- 패킷 시간값이 이전 패킷보다 작거나 같으면 시간 간격이 음수 또는 0이 될 수 있으므로,
  수신 단계는 전달 가능한 원본 시간값을 보존하고 이상 상태를 기록한다.
- 재연결한 소스의 코덱, 해상도 또는 시간 기준이 이전 연결과 다르면 이후 단계가 새
  스트림 특성을 안전하게 처리할 수 있도록 새 스트림 정보를 함께 전달한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 시스템은 설정된 RTSP 주소와 전송 방식을 사용하여 영상 수신을 시도해야
  한다.
- **FR-002**: 시스템은 접근 가능한 RTSP 소스에서 첫 번째 영상 스트림을 식별하고
  영상 패킷만 다음 단계에 전달해야 한다.
- **FR-003**: 시스템은 H.264, H.265 및 HEVC 영상 입력을 지원해야 한다.
- **FR-004**: 시스템은 지원하지 않는 영상 코덱을 감지하면 코덱 이름을 포함한 오류를
  기록하고 해당 입력을 전달해서는 안 된다.
- **FR-005**: 시스템은 전달하는 각 영상 패킷에 코덱, 원본 영상 스트림, 패킷 데이터,
  표시 시간, 디코드 시간, 길이, 키프레임 여부를 보존해야 한다.
- **FR-006**: 시스템은 연속된 유효 패킷의 표시 시간 차이를 패킷 길이로 사용해야 한다.
  차이가 음수이면 길이는 0으로 처리하고, 시간 순서 이상 건수를 5초 단위로 집계하여
  해당 구간에 1건 이상일 때만 경고로 기록해야 한다.
- **FR-007**: 시스템은 표시 시간 또는 디코드 시간이 없는 패킷을 전달하지 않고, 이전
  표시 시간이 있을 경우 시간 정보 이상을 경고로 기록해야 한다.
- **FR-008**: 시스템은 수신 연결 또는 읽기 오류가 발생하면 열려 있는 연결을 정리하고
  3초 후 같은 소스에 다시 연결을 시도해야 한다.
- **FR-009**: 시스템은 연결 시도, 스트림 해상도, 프레임 속도, 코덱, 시간 기준 및
  연결 실패를 운영자가 확인할 수 있는 로그로 기록해야 한다.

### 주요 개체

- **수신 설정**: RTSP 주소와 전송 방식을 나타내며, 하나의 영상 소스를 식별한다.
- **영상 스트림**: 소스의 해상도, 코덱, 프레임 속도, 시간 기준을 포함하는 영상 특성이다.
- **수신 패킷**: 하드웨어 디코드 단계가 소비할 압축 영상 데이터와 원본 시간·키프레임
  메타데이터를 포함한다.

## 성공 기준

### 측정 가능한 결과

- **SC-001**: 접근 가능한 지원 코덱 RTSP 소스에서 수신 시작 후 5초 안에 첫 유효 영상
  패킷을 다음 단계에 전달한다.
- **SC-002**: 10분 동안 안정적인 RTSP 소스를 수신할 때, 시간 정보가 있는 수신 패킷의
  99% 이상이 시간 순서와 키프레임 정보를 보존한다.
- **SC-003**: 일시적으로 단절된 RTSP 소스가 복구된 뒤 5초 안에 자동 재연결 시도를
  시작한다.
- **SC-004**: 지원하지 않는 코덱 또는 연결 오류가 발생하면 1분 안에 원인이 포함된
  운영 로그를 확인할 수 있다.

## 가정

- 입력 RTSP 소스는 하나 이상의 영상 스트림을 제공하며, 오디오 전용 스트림은 대상이 아니다.
- 입력 소스는 지원하는 코덱을 사용하는 동안 해상도와 시간 기준을 안정적으로 제공한다.
- 네트워크와 소스가 복구되면 동일한 설정으로 재연결할 수 있다.
- 후속 디코드 단계는 수신 패킷에 포함된 코덱과 원본 스트림 정보를 소비한다.

## 현재 구현 기준

- 구현 파일은 `src/nvidia_pipe/receive.py`이며 PyAV로 RTSP를 열고
  `rtsp_transport`, 읽기 제한 5초(`rw_timeout=5000000`), 연결 제한 5초를 적용한다.
- 첫 번째 영상 스트림만 소비하며 H.264, H.265/HEVC를
  `PyNvVideoCodec.cudaVideoCodec` 값으로 변환한다.
- 압축 바이트는 ctypes 버퍼로 보관하고, `ReceivedPacket`이 그 버퍼 참조를 유지하여
  NVDEC 호출 전 메모리가 해제되지 않게 한다.
- 연결 또는 읽기 오류(`FFmpegError`, `OSError`, `IndexError`) 뒤에는 컨테이너를 닫고
  3초 후 재시도한다. 지원하지 않는 코덱 오류는 이 복구 대상이 아니다.
