# 기능 명세: NVDEC 영상 디코딩

**기능 식별자**: `002-nvdec-decode`  
**작성일**: 2026-09-14  
**상태**: 초안

## 개요

수신 단계가 전달한 압축 영상 패킷을 GPU 디코더로 처리하여 AI 추론 단계가 사용할 수 있는 GPU 프레임으로 변환한다. 디코딩 결과에는 원본 스트림의 코덱·해상도·시간 기준·PTS와 GPU 식별자가 포함되어야 한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 - 압축 패킷 디코딩 (우선순위: P1)

운영자는 수신된 H.264/H.265 패킷이 지정된 GPU에서 디코딩되어 추론 단계로 전달되기를 원한다.

**검증**: 모의 디코더에 패킷을 전달했을 때 디코더가 생성한 모든 프레임이 순서대로 반환되고 메타데이터가 보존되는지 확인한다.

### 사용자 스토리 2 - 입력 색상 형식 선택 (우선순위: P2)

운영자는 설정으로 native, rgb, rgbp 출력 형식을 선택하고 추론 모델에 맞는 프레임을 받을 수 있어야 한다.

**검증**: 각 설정값이 해당 출력 형식으로 디코더를 초기화하며, 지원하지 않는 값은 명확한 오류로 거부되는지 확인한다.

### 사용자 스토리 3 - 프레임 속도 계산 (우선순위: P3)

운영자는 유효한 PTS 간격을 이용해 스트림의 대표 FPS를 확인할 수 있어야 한다.

**검증**: 증가하는 PTS가 두 개 이상이면 중간값 기반 FPS를 반환하고, 계산 가능한 간격이 없으면 `None`을 반환하는지 확인한다.

## 기능 요구사항

- **FR-001**: 시스템은 수신 패킷을 지정된 GPU와 입력 코덱으로 디코더에 전달해야 한다.
- **FR-002**: 시스템은 `native`, `rgb`, `rgbp` 입력 형식을 지원하고 그 외 형식은 `ValueError`로 거부해야 한다.
- **FR-003**: 시스템은 디코더가 반환한 모든 프레임을 입력 순서대로 하나씩 출력해야 한다.
- **FR-004**: 출력 프레임은 GPU 번호, 코덱 이름, 너비, 높이, 픽셀 형식, 시간 기준, PTS, 프레임 데이터를 보존해야 한다.
- **FR-005**: 디코더는 첫 패킷의 스트림 시간 기준을 이후 출력 프레임에 사용해야 한다.
- **FR-006**: FPS 계산은 증가하는 PTS 간격의 중간값과 시간 기준을 사용해야 하며, 유효한 간격이 없거나 PTS가 2개 미만이면 `None`을 반환해야 한다.
- **FR-007**: 디코더 초기화와 패킷 처리는 입력 순서를 유지하며, 모의 디코더 기준 패킷당 100ms 이내에 다음 단계로 전달되어야 한다.

## 성공 기준

- **SC-001**: 모의 디코더 검증에서 입력 패킷 100개 이상을 누락 없이 동일 순서로 출력한다.
- **SC-002**: 지원 형식 3종 각각의 초기화 검증이 100% 통과한다.
- **SC-003**: 잘못된 형식과 계산 불가 PTS 입력이 예외 또는 `None`으로 일관되게 처리된다.
- **SC-004**: 출력 프레임 메타데이터 필드가 테스트에서 100% 원본 또는 디코더 결과와 일치한다.

## 가정 및 범위

- GPU 디코더와 수신 단계가 제공하는 객체의 수명은 호출자가 보장한다.
- 디코더 재연결과 RTSP 입력 복구는 `receive.py`의 책임이며 이 기능 범위에 포함하지 않는다.
- 오디오 디코딩은 범위에 포함하지 않는다.

## 추가 운영 계약

- 디코더는 첫 패킷에서 한 번만 생성하며 빈 입력에서는 생성하지 않는다.
- 디코더 설정은 device memory 사용과 native latency를 적용한다.
- FPS 계산은 현재 종단 파이프라인의 필수 출력이 아니며 별도 모니터링 호출에서 사용한다.
- 디코더 예외는 별도 복구하지 않고 상위 호출자에게 전파한다.

## 현재 구현 기준

- 구현 파일은 `src/nvidia_pipe/decode.py`이다. `decode()`는 선택적
  `torch.cuda.Stream`을 받고, 전달되면 그 native handle을 `cudastream`으로
  NVDEC 생성자에 전달한다.
- NVDEC는 device memory와 native latency로 초기화된다. 입력 프레임은 CPU 배열로
  변환하지 않고 `GpuFrame.frame_data`로 다음 단계에 전달된다.
- 픽셀 형식과 시간 기준은 첫 패킷에서 초기화한 디코더와 스트림에서 결정하며,
  프레임 PTS는 디코더가 반환한 값(`getPTS()`)을 사용한다.
