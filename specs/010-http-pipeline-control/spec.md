# 기능 명세: HTTP 파이프라인 제어

**기능 식별자**: `010-http-pipeline-control`  
**작성일**: 2026-09-15  
**상태**: Draft

## 사용자 시나리오 및 검증

### 사용자 스토리 1 - 파이프라인 시작과 중지 (우선순위: P1)

운영자는 등록된 개별 영상 파이프라인을 필요할 때 시작하거나 중지한다. 시작 또는 중지 요청의 결과로 해당 파이프라인의 현재 상태를 확인한다.

**우선순위 근거**: 실행 중인 영상 처리 작업을 선택적으로 제어하는 것이 이 기능의 핵심 가치다.

**독립 검증**: 하나의 등록 파이프라인에 시작 요청과 중지 요청을 차례로 보내고 상태가 `running`, `stopped`로 전환되는지 확인한다.

**승인 시나리오**:

1. **Given** 중지된 등록 파이프라인, **When** 운영자가 시작을 요청하면, **Then** 파이프라인은 별도 실행 단위로 시작되고 실행 상태가 반환된다.
2. **Given** 실행 중인 등록 파이프라인, **When** 운영자가 중지를 요청하면, **Then** 해당 실행 단위가 정리되고 중지 상태가 반환된다.
3. **Given** 이미 실행 중인 파이프라인, **When** 운영자가 다시 시작을 요청하면, **Then** 중복 실행 단위를 만들지 않고 기존 실행 상태가 반환된다.

---

### 사용자 스토리 2 - 파이프라인 상태 조회 (우선순위: P2)

운영자는 등록된 모든 파이프라인과 특정 파이프라인의 상태를 조회해 운영 현황과 비정상 종료 여부를 판단한다.

**우선순위 근거**: 제어 요청의 결과와 비정상 종료를 확인할 수 있어야 안전하게 운영할 수 있다.

**독립 검증**: 등록 목록을 조회하고 각 항목의 이름, 상태, 실행 식별 정보 및 종료 정보를 확인한다.

**승인 시나리오**:

1. **Given** 하나 이상의 등록 파이프라인, **When** 운영자가 목록을 조회하면, **Then** 모든 등록 항목의 상태가 반환된다.
2. **Given** 실행 단위가 비정상 종료한 파이프라인, **When** 운영자가 상태를 조회하면, **Then** 상태는 `failed`이고 종료 정보를 포함한다.
3. **Given** 등록되지 않은 이름, **When** 운영자가 상태 조회·시작·중지를 요청하면, **Then** 요청이 거부되고 대상이 없음을 알 수 있다.

---

### 사용자 스토리 3 - 브라우저로 제어 (우선순위: P3)

운영자는 별도 API 도구 없이 브라우저 화면에서 파이프라인 목록을 보고 시작·중지하며, 각 파이프라인의 RTSP 수신·송신 연결 상태를 구분해 확인할 수 있다.

**우선순위 근거**: 일상 운영에서 빠르게 현황을 확인하고 조치할 수 있다.

**독립 검증**: 로컬 브라우저에서 제어 화면을 열고 목록, 실행 상태, 수신·송신 RTSP 연결 상태를 확인한 뒤 한 항목을 시작 또는 중지한다.

**승인 시나리오**:

1. **Given** 제어 서비스가 실행 중일 때, **When** 운영자가 기본 화면을 열면, **Then** 등록 파이프라인, 최신 실행 상태, 수신 RTSP 상태 및 송신 RTSP 상태가 각각 표시된다.
2. **Given** 제어 화면의 파이프라인 항목, **When** 운영자가 시작 또는 중지 동작을 선택하면, **Then** 요청 결과가 화면의 상태에 반영된다.
3. **Given** 실행 중인 파이프라인의 수신 또는 송신 RTSP가 끊겼을 때, **When** 운영자가 기본 화면을 확인하면, **Then** 실행 상태와 독립적으로 해당 연결 상태가 끊겼음을 알 수 있다.
4. **Given** 파이프라인 카드가 `stopped` 상태일 때, **When** 운영자가 기본 화면을 확인하면, **Then** 입력과 출력 RTSP 상태는 모두 `disconnected`로 표시된다.
5. **Given** 브라우저의 상태 조회 요청이 실패했을 때, **When** 이전에 표시한 파이프라인 카드가 있을 때, **Then** 해당 카드는 `stopped` 및 `disconnected` 상태로 표시되어 오래된 정상 상태를 유지하지 않는다.

### 예외 상황

- 제어 서비스가 시작될 때 파이프라인 목록에 같은 이름이 둘 이상 있으면, 어떤 파이프라인도 실행하지 않고 원인을 알린다.
- 등록 설정 또는 개별 파이프라인 설정을 읽을 수 없으면, 제어 서비스는 시작하지 않고 문제 파일을 알린다.
- 중지 요청 후 정해진 시간 안에 실행 단위가 끝나지 않으면, 운영자가 요청한 중지가 완료되도록 강제 종료한다.
- 제어 서비스가 종료되면 실행 중인 모든 자식 실행 단위를 정리한다.

## 요구 사항

### 기능 요구 사항

- **FR-001**: 시스템은 파이프라인 목록 설정에서 등록된 파이프라인과 고유 이름을 읽어야 한다.
- **FR-002**: 시스템은 등록된 각 파이프라인을 독립 실행 단위로 시작할 수 있어야 한다.
- **FR-003**: 시스템은 실행 중인 파이프라인을 개별적으로 중지하고, 정상 종료가 지연되면 제한 시간 뒤 강제 종료해야 한다.
- **FR-004**: 시스템은 동일한 파이프라인의 중복 시작 요청에 대해 추가 실행 단위를 만들지 않아야 한다.
- **FR-005**: 시스템은 등록된 모든 파이프라인과 특정 파이프라인의 이름, 상태, 실행 식별 정보, 설정 위치 및 종료 정보를 조회 가능하게 해야 한다.
- **FR-006**: 시스템은 아직 시작하지 않았거나 명시적으로 중지한 파이프라인을 `stopped`, 실행 중인 파이프라인을 `running`, 요청 없이 종료된 파이프라인을 `failed` 상태로 구분해야 한다.
- **FR-007**: 시스템은 브라우저와 프로그램 기반 클라이언트에서 목록 조회, 상태 조회, 시작 및 중지 기능을 제공해야 한다.
- **FR-008**: 시스템은 존재하지 않는 파이프라인 요청을 명확히 거부해야 한다.
- **FR-009**: 시스템은 기본 설정에서 로컬 장비에서만 제어 서비스에 접근할 수 있어야 하며, 운영자가 명시적으로 바인딩 주소와 포트를 변경할 수 있어야 한다.
- **FR-010**: 시스템은 서비스 종료 시 시작한 모든 파이프라인 실행 단위를 정리해야 한다.
- **FR-011**: 시스템은 시작·중지·강제 종료 및 요청 처리를 운영 로그에 기록해야 한다.
- **FR-012**: 시스템은 각 파이프라인의 수신 RTSP 상태와 송신 RTSP 상태를 상태 조회 응답 및 브라우저 화면에서 실행 상태와 구분해 제공해야 한다.
- **FR-013**: 시스템은 브라우저 카드가 `stopped` 상태이면 입력과 출력 RTSP 상태를 모두 `disconnected`로 표시해야 한다.
- **FR-014**: 시스템은 브라우저의 상태 조회 요청이 실패하거나 실패 응답을 반환하면, 이전에 표시한 카드의 실행 상태를 `stopped`, Endpoint 및 RTSP 상태를 `disconnected`로 표시해야 한다.
- **FR-015**: 시스템은 동일한 파이프라인의 상태 갱신 시 기존 브라우저 카드와 제어 요소를 유지하고, 변경된 상태·Endpoint·통계 값만 갱신해야 한다.

### 주요 엔터티

- **파이프라인 정의**: 고유 이름과 해당 영상 처리 설정의 위치로 구성된 제어 대상이다.
- **파이프라인 실행 단위**: 하나의 파이프라인 정의에 대해 생성된 독립 실행 단위이며, 실행 식별 정보와 종료 정보를 가진다.
- **파이프라인 상태**: `stopped`, `running`, `failed` 중 하나이며, 운영자에게 해당 정의의 현재 실행 결과를 나타낸다.
- **RTSP 연결 상태**: 입력 또는 출력 RTSP 각각의 현재 연결 상태이며, `disconnected`, `connected` 중 하나다. 파이프라인 실행 상태와 별도로 표시된다.

## 성공 기준

- **SC-001**: 운영자는 등록된 파이프라인을 시작 또는 중지한 뒤 5초 이내에 결과 상태를 확인할 수 있다.
- **SC-002**: 동일 파이프라인에 연속된 시작 요청 100회를 보내도 실행 단위는 하나만 유지된다.
- **SC-003**: 등록된 모든 파이프라인의 목록 조회는 1초 이내에 각 항목의 이름과 상태를 표시한다.
- **SC-004**: 제어 서비스 종료 요청 후 시작된 모든 자식 실행 단위가 5초 이내에 종료된다.
- **SC-005**: 운영자는 실행 중인 파이프라인의 수신·송신 RTSP 연결 상태 변화를 다음 상태 갱신 주기 안에 화면과 상태 조회에서 각각 확인할 수 있다.
- **SC-006**: 상태 조회가 실패한 뒤 다음 갱신 시도 안에, 기존 카드에서 실행·Endpoint·RTSP 상태가 모두 안전 상태로 표시된다.

## 가정 및 범위

- 파이프라인의 등록과 영상 처리 설정 변경은 기존 YAML 파일 관리 방식으로 수행하며, 이 기능은 설정 생성·수정·삭제를 제공하지 않는다.
- 기본 배포 대상은 신뢰할 수 있는 로컬 운영자다. 원격 공개 접근용 인증·권한 관리는 이번 범위에 포함하지 않는다.
- 자동 재시작, 작업 이력 영속화, 실시간 로그 스트리밍은 이번 범위에 포함하지 않는다.
- 상태 조회 API가 반환하는 RTSP 상태와 달리, 브라우저 화면은 `stopped` 또는 상태 조회 실패 시 운영자 혼동을 막기 위해 두 RTSP 상태를 `disconnected`로 표시한다.
