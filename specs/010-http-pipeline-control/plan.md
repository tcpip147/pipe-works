# 구현 계획: HTTP 파이프라인 제어

**브랜치**: `010-http-pipeline-control` | **작성일**: 2026-09-15 | **명세**: [spec.md](spec.md)

## 요약

`plumber`를 즉시 일괄 실행하는 명령줄 도구에서, 등록 파이프라인을 HTTP 요청과 브라우저 화면으로 개별 제어하는 로컬 운영 서비스로 전환한다. 영상 처리 수명 주기는 계속 `nvidia_pipe`가 담당하고, `plumber`는 정의 로드, 자식 프로세스 생성·상태 관찰·종료 정리만 담당한다.

## 기술 맥락

**언어/버전**: Python 3.11.9  
**주요 의존성**: 표준 라이브러리 HTTP 서버·멀티프로세싱, PyYAML  
**저장소**: 기존 YAML 설정 파일; 실행 이력 영속화 없음  
**테스트**: `unittest`  
**대상 환경**: Windows 로컬 운영 환경  
**프로젝트 유형**: 단일 Python 프로젝트 내 로컬 웹 서비스  
**성능 목표**: 목록·상태 조회 1초 이내  
**제약 사항**: 기본 루프백 바인딩, 외부 공개 인증은 범위 밖, 자식 프로세스는 `spawn` 컨텍스트 사용  
**규모/범위**: YAML에 등록된 소수의 로컬 영상 파이프라인을 단일 운영자가 제어

## 헌장 검토

- 실시간 영상 수신·디코딩·추론·인코딩 경로는 변경하지 않는다. 통과.
- GPU 자원 격리와 파이프라인별 독립 프로세스를 유지한다. 통과.
- plumber는 영상 처리 대신 감독 책임만 가진다. 통과.
- 정상 종료와 제한 시간 뒤 강제 종료를 제공한다. 통과.
- 시작·중지·HTTP 요청을 운영 로그에 남긴다. 통과.
