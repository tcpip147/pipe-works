# 기능 명세: Process 관리 모듈

**기능 식별자**: `014-process-module`  
**작성일**: 2026-09-19  
**상태**: 초안

## 개요

Process 관리 모듈은 저장된 영상 프로세스 정의와 실제 실행 프로세스, 그리고 각 StreamProcess의 제어 연결을 일관되게 관리한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 - 프로세스 수명주기 관리 (우선순위: P1)

운영자는 등록한 프로세스를 시작, 정지, 수정, 삭제하고 실제 실행 상태를 확인한다.

**독립 검증**: 프로세스를 등록한 뒤 시작과 정지를 수행하고, 동일 식별자의 중복 실행이 생기지 않는지 확인한다.

**인수 시나리오**:

1. **조건** 정지된 등록 프로세스가 있을 때, **동작** 시작을 요청하면, **결과** 해당 식별자의 실행 프로세스가 하나만 생성된다.
2. **조건** 실행 중인 프로세스가 있을 때, **동작** 정지를 요청하면, **결과** 해당 프로세스만 종료 절차를 시작한다.
3. **조건** 실행 중인 프로세스일 때, **동작** 삭제를 요청하면, **결과** 정의는 삭제되지 않는다.

### 사용자 스토리 2 - 프로세스 이벤트 중개 (우선순위: P1)

운영자는 특정 StreamProcess가 보낸 준비, 오류, 로그 이벤트를 해당 프로세스와 연결해 확인할 수 있다.

**독립 검증**: 두 StreamProcess가 각각 로그를 보낼 때, 수신 이벤트가 올바른 프로세스 식별자를 가진다는 것을 확인한다.

**인수 시나리오**:

1. **조건** StreamProcess가 연결되었을 때, **동작** 준비 메시지를 교환하면, **결과** 해당 프로세스 연결만 활성 상태가 된다.
2. **조건** 로그 이벤트를 수신했을 때, **동작** 상위 이벤트 수신자에게 전달하면, **결과** 프로세스 식별자와 원래 로그 정보가 보존된다.
3. **조건** 연결이 종료되었을 때, **동작** 종료를 감지하면, **결과** 해당 연결만 제거된다.

### 예외 상황

- 이미 실행 중인 프로세스의 시작 요청은 중복 실행을 만들지 않는다.
- 존재하지 않는 프로세스 작업은 다른 프로세스의 상태를 변경하지 않는다.
- 한 프로세스의 연결 오류는 다른 프로세스의 연결을 종료하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: 시스템은 프로세스 식별자와 스트림 실행 설정으로 구성된 프로세스 정의를 저장하고 조회해야 한다.
- **FR-002**: 시스템은 동일 식별자의 동시 실행을 허용하지 않아야 한다.
- **FR-003**: 시스템은 프로세스별 제어 연결을 독립적으로 추적해야 한다.
- **FR-004**: 시스템은 StreamProcess 로그 이벤트에 프로세스 식별자를 추가해 상위 이벤트 수신자에게 전달해야 한다.
- **FR-005**: 시스템은 실행 중인 프로세스의 삭제를 거부해야 한다.
- **FR-006**: 시스템은 연결 종료 또는 오류가 해당 프로세스의 연결 상태에만 영향을 주게 해야 한다.

### 주요 개체

- **프로세스 정의**: 운영자가 저장한 프로세스 식별자와 실행 설정이다.
- **실행 프로세스**: 운영체제에서 실행 중인 하나의 StreamProcess다.
- **프로세스 연결**: 관리 모듈과 특정 StreamProcess 사이의 제어 및 이벤트 채널이다.
- **프로세스 이벤트**: 준비, 종료, 오류, 로그를 나타내며 프로세스 식별자를 포함한다.

## 성공 기준

- **SC-001**: 동일 식별자에 대한 연속 시작 요청 100회에서 중복 실행은 0회다.
- **SC-002**: 연결된 프로세스의 로그 이벤트는 1초 안에 상위 이벤트 수신자에게 전달된다.
- **SC-003**: 한 프로세스 연결의 종료가 다른 실행 프로세스의 제어 가능 여부를 변경하지 않는다.

## 가정

- 모든 관리 대상 프로세스는 동일 호스트에서 실행된다.
- 프로세스 식별자는 저장 후 변경하지 않는다.
