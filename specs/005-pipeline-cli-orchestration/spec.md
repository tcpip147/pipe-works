# 기능 명세: 단일 파이프라인 오케스트레이션

**기능 식별자**: `005-pipeline-cli-orchestration`

## 개요

설정 파일과 추론 모듈을 로드하고 RTSP 수신부터 디코드·추론·인코드·송출까지 한 파이프라인으로 연결한다.

## 기능 요구사항

- **FR-001**: 기본 또는 지정된 YAML 설정 파일을 읽고 필수 설정이 없으면 명확한 오류를 반환해야 한다.
- **FR-002**: 모델 파일을 동적으로 로드하고 `on_frame(frame, infer=...)` 호출 계약을 적용해야 한다.
- **FR-003**: `interval_frames`에 따라 추론 실행 여부를 결정하고 0이면 프레임을 그대로 전달해야 한다.
- **FR-004**: 추론 실패 시 오류를 기록하고 원본 GPU 프레임을 다음 단계로 전달해야 한다.
- **FR-005**: 단계 순서를 receive → decode → inference → encode → send로 보장해야 한다.
- **FR-006**: Ctrl+C 또는 예외 발생 시 Sender를 정리하고 종료해야 한다.
- **FR-007**: 지원하지 않는 frame type과 인코딩 패킷 형식은 명확한 오류로 거부해야 한다.
- **FR-008**: Windows에서 CUDA 런타임이 설치된 경우, 파이프라인 시작 전에 CUDA 환경 변수에 지정된 실행 라이브러리 경로를 사용할 수 있어야 한다. CUDA 환경 변수가 없거나 해당 경로가 없더라도 구성 확인 과정은 실패하지 않아야 한다.
- **FR-009**: 기본 추론 모듈은 추론 주기에 따라 최신 표시 결과를 갱신하고, 비추론
  프레임에서는 직전 표시 결과를 재사용할 수 있어야 한다.
- **FR-010**: 각 파이프라인 설정 파일은 비어 있지 않은 `name`을 포함해야 하며, 이 이름은 해당 파이프라인의 식별과 로그 표기에 사용되어야 한다.

## 성공 기준

- **SC-001**: 유효한 설정에서 전체 단계가 순서대로 연결된다.
- **SC-002**: 추론 오류가 발생해도 파이프라인이 중단되지 않고 원본 프레임이 전달된다.
- **SC-003**: 종료 요청 후 Sender가 5초 이내 정리된다.
- **SC-004**: CUDA 런타임 경로가 설정된 Windows 환경에서 파이프라인이 추론 모듈을 로드하기 전에 해당 경로를 인식하며, CUDA 런타임 경로가 설정되지 않은 환경에서도 설정 검증은 정상 완료된다.
- **SC-005**: 기본 추론 예제는 연속된 비추론 프레임에서 가장 최근 표시 결과를 유지해 오버레이한다.
- **SC-006**: 이름이 없는 파이프라인 설정은 시작 전에 명확한 오류로 거부되고, 유효한 이름을 가진 설정은 해당 이름으로 식별된다.

## 구현 계약

- 기본 설정 파일은 `application.yml`이며 `--config`로 경로를 지정할 수 있다.
- 추론 모듈은 `on_frame(frame, infer=...)` 함수를 제공해야 한다.
- `frame_type`은 현재 `pytorch`만 지원하며, 다른 값은 `ValueError`로 처리한다.
- `encoded_bytes()`는 bytes 계열과 중첩 dict/list/tuple의 바이트 값을 지원한다.
- 설정·모델 로딩 및 단계 초기화 오류는 호출자에게 전파하고, 프레임 처리 중 추론 오류는 원본 프레임으로 대체한다.
- 파이프라인 설정의 최상위 `name`은 비어 있지 않은 문자열이어야 한다. 입력·출력·추론 설정과 함께 단일 파이프라인 설정의 일부이며, 이름의 전역 중복 여부는 다중 파이프라인 감독기의 책임이다. 파이프라인 시작 후 모든 로그는 이 이름을 첫 식별자로 표시한다.
- CUDA DLL 경로 준비는 `CUDA_PATH` 및 `CUDA_PATH_V12_6` 환경 변수의 `bin` 및 `bin/x64` 하위 경로를 대상으로 하며, 존재하는 경로만 추가한다.
- 현재 기본 예제는 `examples/inference.py` 하나이며 CUDA YOLO 예제 또는
  `YOLO_MODEL`/`YOLO_CONF` 설정은 제공하지 않는다.
- 설치된 콘솔 명령 `pipe-works`는 단일 파이프라인 CLI를 시작한다.

## 현재 구현 기준

- 구현 파일은 `src/nvidia_pipe/cli.py`이다. 파이프라인 시작 시 GPU별
  `torch.cuda.Stream` 하나를 만들고 decode, PyTorch 추론, encode에 같은 stream을
  전달한다.
- 추론 간격이 0이면 프레임을 추론 모듈에 전달하지 않고 그대로 인코더로 넘긴다.
  0보다 크면 첫 프레임부터 `frame_index % interval_frames == 0`인 프레임에
  `infer=True`를 전달한다.
- 인코더가 만든 패킷 데이터는 RTSP 송출 큐에 넣기 직전 `encoded_bytes()`로 CPU bytes로
  변환한다. 이 단계 전까지 프레임 픽셀 데이터는 GPU 경로에 있다.
