# 기능 명세: Stream 실행 모듈

**기능 식별자**: `015-stream-module`  
**작성일**: 2026-09-19  
**상태**: 초안

## 개요

Stream 실행 모듈은 하나의 영상 프로세스 안에서 제어 메시지 수신, 로그 전달, 영상 파이프라인 실행 진입점을 분리한다. 로그나 제어 통신이 영상 처리 흐름을 막지 않아야 한다.

## 사용자 시나리오 및 검증

### 사용자 스토리 1 - 독립된 파이프라인 실행 (우선순위: P1)

운영자는 StreamProcess 시작 뒤 파이프라인 실행과 제어 메시지 처리가 서로 막지 않기를 원한다.

**독립 검증**: 파이프라인 실행 흐름이 활성인 동안 준비 메시지를 보내 1초 안에 응답하는지 확인한다.

**인수 시나리오**:

1. **조건** StreamProcess가 시작될 때, **동작** 파이프라인을 시작하면, **결과** 파이프라인과 제어 수신 흐름이 각각 활성화된다.
2. **조건** 종료 요청을 받았을 때, **동작** 파이프라인에 종료를 요청하면, **결과** 종료 절차가 시작된다.

### 사용자 스토리 2 - 최신 로그 우선 전달 (우선순위: P1)

운영자는 영상 처리 성능을 해치지 않으면서 최근 로그를 관리 서비스에서 확인할 수 있어야 한다.

**독립 검증**: 로그를 빠르게 발생시키고 수신 측을 지연시킨 뒤, 영상 처리 흐름이 로그 전송을 기다리지 않는지 확인한다.

**인수 시나리오**:

1. **조건** 로그가 생성될 때, **동작** 로그를 전달 대기열에 넣으면, **결과** 영상 처리 흐름은 전송 완료를 기다리지 않는다.
2. **조건** 로그 대기열이 가득 찰 때, **동작** 새 로그가 도착하면, **결과** 가장 오래된 로그가 제거되고 최신 로그가 보존된다.
3. **조건** 관리 서비스 연결이 복구될 때, **동작** 보존된 로그가 있으면, **결과** 최신 보존 로그의 전달을 재개한다.

### 사용자 스토리 3 - 프로세스별 제어 채널 (우선순위: P2)

운영자는 특정 StreamProcess에만 준비 및 정지 요청을 보낼 수 있어야 한다.

**독립 검증**: 두 프로세스 중 하나에만 정지 요청을 보내고 다른 프로세스가 유지되는지 확인한다.

### 예외 상황

- 로그 수신자가 없어도 영상 파이프라인과 제어 채널은 계속 동작한다.
- 로그 전송 실패는 영상 처리 실패로 처리하지 않는다.
- 잘못된 제어 메시지는 파이프라인을 중단하지 않고 오류로 기록한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 시스템은 각 StreamProcess에 하나의 고유 프로세스 식별자를 사용해야 한다.
- **FR-002**: 시스템은 제어 메시지 수신과 영상 파이프라인 실행을 독립된 실행 흐름으로 운영해야 한다.
- **FR-003**: 시스템은 GPU 및 영상 처리 자원을 파이프라인 실행 흐름 안에서 초기화하고 사용해야 한다.
- **FR-004**: 시스템은 로그 생성 경로가 전송 완료를 기다리지 않게 해야 한다.
- **FR-005**: 시스템은 로그 대기열 포화 시 가장 오래된 항목을 버리고 최신 항목을 보존해야 한다.
- **FR-006**: 시스템은 활성 제어 연결에서 준비 및 정지 요청에 응답해야 한다.
- **FR-007**: 시스템은 정지 요청 시 파이프라인, 로그 전달, 제어 채널의 정리를 시작해야 한다.
- **FR-008**: 시스템은 로그 이벤트에 시간, 수준, 로거, 메시지와 가능한 예외 정보를 포함해야 한다.

### 주요 개체

- **StreamProcess**: 하나의 관리 대상 영상 스트림을 실행하고 제어하는 독립 프로세스다.
- **파이프라인 실행 흐름**: 영상 수신, 처리, 송출을 담당하는 전용 실행 흐름이다.
- **제어 연결**: 관리 서비스가 특정 StreamProcess에 요청을 보내는 채널이다.
- **로그 대기열**: 영상 처리와 분리되어 최신 로그를 보존하는 제한된 전달 대기열이다.

## 성공 기준

- **SC-001**: 파이프라인이 실행 중일 때 준비 요청은 1초 안에 응답한다.
- **SC-002**: 로그 수신자가 지연되거나 없더라도 로그 생성으로 영상 처리 흐름이 대기하지 않는다.
- **SC-003**: 로그 대기열 포화 시험에서 보존된 모든 항목은 가장 최근에 생성된 항목들이다.
- **SC-004**: 두 StreamProcess 중 하나만 정지해도 다른 StreamProcess의 제어 연결과 파이프라인 실행은 유지된다.

## 가정

- StreamProcess 하나는 하나의 영상 파이프라인을 소유한다.
- 영상 수신·추론·인코딩의 구체 구현은 `Pipeline.run()` 진입점에 배치한다.
