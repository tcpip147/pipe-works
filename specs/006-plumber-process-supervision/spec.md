# 기능 명세: 다중 파이프라인 프로세스 감독

**기능 식별자**: `006-plumber-process-supervision`

## 기능 요구사항

- **FR-001**: `plumber.yml`의 pipelines 목록에 정의된 모든 파이프라인을 독립 프로세스로 시작해야 한다.
- **FR-002**: `plumber.yml`의 각 항목에서는 파이프라인 설정 파일 경로만 지정하고, 해당 설정 파일의 `name`을 읽어 프로세스 이름과 로그 식별자에 적용해야 한다.
- **FR-003**: 하나의 파이프라인이 비정상 종료하면 해당 exit code와 이름을 기록하고 plumber도 실패 상태로 종료해야 한다.
- **FR-004**: Ctrl+C 또는 종료 시 모든 시작된 자식 프로세스를 terminate하고 제한 시간 후 kill해야 한다.
- **FR-005**: 시작되지 않은 프로세스에는 종료 작업을 수행하지 않아야 한다.
- **FR-006**: 각 파이프라인은 독립 설정 파일을 사용하며 GPU 번호 충돌 검사는 범위 밖으로 명시한다.
- **FR-007**: 사용자는 설치된 `plumber` 콘솔 명령 또는 제공된 Windows 실행 스크립트로 `plumber.yml` 기반 다중 파이프라인 감독기를 시작할 수 있어야 한다.
- **FR-008**: 감독기는 참조된 모든 파이프라인 설정의 `name`이 고유한지 확인하고, 중복된 이름이 있으면 어떤 자식 프로세스도 시작하지 않은 채 명확한 오류로 거부해야 한다.

## 성공 기준

- **SC-001**: 설정된 파이프라인 수만큼 프로세스가 시작된다.
- **SC-002**: 종료 요청 후 모든 자식 프로세스가 5초 이내 수거된다.

## 구현 계약

- `plumber.yml`의 `pipelines` 목록은 각 항목에 `config`만 포함한다. `name`은 참조된 개별 파이프라인 설정 파일의 최상위 속성이다.
- 감독기는 프로세스를 시작하기 전에 모든 참조 설정의 이름을 읽고 중복 여부를 확인한다.
- 파이프라인은 `multiprocessing`의 `spawn` 컨텍스트로 생성된다.
- 비정상 자식이 있으면 개별 파이프라인 설정에서 읽은 이름 목록을 포함한 `RuntimeError`를 발생시킨다.
- 시작되지 않은 프로세스에는 종료·수거 작업을 수행하지 않는다.
- 설치된 콘솔 명령 `plumber`는 다중 파이프라인 감독 CLI를 시작한다. `run.bat`은 프로젝트 가상환경의 Python으로 `plumber.yml` 기반 감독기를 시작한다.

## 현재 구현 기준

- 구현 파일은 `src/plumber/cli.py`이다. 모든 설정 파일을 먼저 해석하고 이름 중복을
  검사한 뒤에만 자식 프로세스를 시작한다.
- 프로세스는 `multiprocessing.get_context("spawn")`으로 만들며, 각 자식의 진입점은
  `nvidia_pipe.cli.run_pipeline_entry`이다.
- 종료 시 살아 있는 프로세스만 terminate, join(3초), kill, join(2초) 순서로 수거한다.
